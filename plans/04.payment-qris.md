# 04. QRIS Payment Integration

## Overview

Payment flow using QRIS (Quick Response Code Indonesian Standard). Placeholder implementation with webhook callback architecture ready for real provider integration.

## QRIS Flow

```
User clicks "Bayar Sekarang"
        │
        ▼
POST /api/tickets → Create ticket (PENDING)
        │
        ▼
POST /api/tickets/[id]/pay → Create payment + generate QRIS payload
        │
        ▼
Display QR code to user
        │
        ├─ User scans with e-wallet/banking app
        │
        ▼
Payment provider processes payment
        │
        ▼
POST /api/payments/webhook → Provider sends callback
        │
        ▼
Mark payment SUCCESS → Generate approval code → Update location balance
        │
        ▼
Redirect to /tiket/[ticketId]
```

## Placeholder QRIS Implementation

### QRIS Payload Generation

Located at `src/lib/qris.ts`:

```typescript
interface QRISPayload {
  ticketId: string;
  amount: number;
  merchantName: string;
  locationName: string;
  timestamp: string;
}
```

The placeholder generates a JSON string containing payment details. When a real provider is integrated, replace this with the actual QRIS string format (following Bank Indonesia's QRIS specification).

### QR Code Image Generation

Use the `qrcode` npm package:

- Size: 512×512 for display, 1024×1024 for download
- Error correction level: M
- Include padding
- Add label text below QR (plate + amount)

### QR Download Feature

- Generate high-res PNG
- Embed ticket info (plate, amount, location) as text overlay
- Use `sharp` for image compositing
- Client-side download via `<a download>` or `canvas.toBlob()`

## Payment Expiry

- QRIS codes expire after 15 minutes (configurable per location)
- `qrisExpiry` = `createdAt + 15 minutes`
- Client shows countdown timer
- On expiry, ticket status remains `PENDING` but payment is `EXPIRED`
- User can regenerate QRIS via `POST /api/tickets/[id]/pay` again

## Webhook Handler

### Endpoint: `POST /api/payments/webhook`

**For placeholder:**

- Accept a simulated webhook payload
- Validate: ticket exists, amount matches, payment is PENDING
- Update payment status to SUCCESS
- Generate approval codes
- Update location balance
- Return 200

**For production integration:**

- Validate webhook signature (provider-specific)
- Idempotent: check if payment already processed
- Store raw webhook payload for audit
- Process asynchronously if needed

## Payment Status Polling

### Endpoint: `GET /api/payments/[id]/status`

Returns current payment status for client-side polling:

```json
{
  "id": "clx...",
  "status": "PENDING",
  "paidAt": null
}
```

Client polls every 3 seconds while displaying the QR code. On status change to `SUCCESS`, redirect to ticket page.

## Approval Code Generation

Located at `src/lib/approval-code.ts`:

```typescript
function generateApprovalCode(ticketId: string): {
  approvalCode: string; // 4-digit random
  timeoutCode: string; // 4-digit from expiry
};
```

**Approval code**: `Math.floor(1000 + Math.random() * 9000)` → e.g., `4827`

**Timeout code**: Derive 4 digits from `validUntil` timestamp:

- Take `validUntil.getTime()`
- Apply simple hash: `(ts % 97 * 31 + ts % 53) % 10000`
- Pad to 4 digits → e.g., `6301`

**Display**: `4827 - 6301`

**QR payload**: `PARKIR:{ticketId}:{approvalCode}:{timeoutCode}`

## Location Balance Update

On successful payment:

1. Read current `ParkingLocation.balance`
2. Add `payment.amount` to balance
3. Update in same transaction as payment confirmation

```sql
UPDATE "ParkingLocation"
SET balance = balance + $1
WHERE id = $2
```

## Future: Real QRIS Integration

When switching to a real provider (Midtrans, Xendit, etc.):

1. Replace `generateQRISPayload()` with provider API call
2. Add provider credentials to `.env`
3. Implement provider-specific webhook signature validation
4. Handle provider-specific error codes
5. May need server-to-server API calls for:
   - Creating QRIS transaction
   - Checking transaction status
   - Cancelling expired transactions

The placeholder architecture keeps these changes isolated to `src/lib/qris.ts` and the webhook handler.
