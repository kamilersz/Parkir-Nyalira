# 02. User Parking Flow

## Overview

The main user journey: scan QR → input plate → select duration → pay → get approval code.

## URL Structure

```
/parkir/[slug]              → Main parking flow (multi-step form)
/tiket/[ticketId]           → View ticket status & approval code
/riwayat                    → User's parking history (requires auth)
```

## Step-by-Step Flow

### Step 1: Location Loading

When user opens `/parkir/[slug]`:

1. Fetch location data: `GET /api/locations/[slug]`
2. Returns: location name, pricing mode, pricing tiers, vehicle type rules
3. If location not found or inactive → show 404
4. If location found → show location header (name, address) and proceed to Step 2

### Step 2: License Plate & Vehicle Type

**UI Components:**

- Input field for license plate with formatting hint
- Auto-detected vehicle type badge (updates in real-time as user types)
- Manual vehicle type selector (dropdown) as override
- For logged-in users: quick-select from saved plates

**Logic:**

1. User types plate number
2. On each keystroke, normalize the plate and run against `VehicleTypeRule` regex patterns (sorted by priority desc)
3. First matching rule determines the vehicle type
4. User can override auto-detected type via dropdown
5. If no rules match, default to `CAR` and require manual selection

**Plate normalization:**

- Strip all spaces and dashes
- Convert to uppercase
- Store both normalized (`B1234ABC`) and raw (`B 1234 ABC`) versions

### Step 3: Duration Selection

**UI Components:**

- Quick-select buttons: 1 jam, 2 jam, 3 jam, 5 jam, 1 hari
- Custom duration input (hours + minutes)
- Real-time price calculation display

**Logic:**

- Based on location's `pricingMode`:
  - `FLAT_HOURLY`: Calculate using first hour rate + additional hour rates
  - `FIXED_DAILY`: Show single flat rate regardless of duration
- Grace period applied (free minutes before charging starts — informational only)
- Price updates instantly when duration or vehicle type changes

### Step 4: Price Summary & Confirm

**UI Display:**

- Location name
- Vehicle type
- License plate
- Duration
- Price breakdown (first hour, additional hours, total)
- "Bayar Sekarang" (Pay Now) button

**API Call:** `POST /api/tickets`

```json
{
  "locationSlug": "mall-xyz",
  "licensePlate": "B 1234 ABC",
  "vehicleType": "CAR",
  "durationMinutes": 120
}
```

**Response:**

```json
{
  "ticket": {
    "id": "clx...",
    "licensePlate": "B 1234 ABC",
    "vehicleType": "CAR",
    "durationMinutes": 120,
    "totalPrice": 15000,
    "status": "PENDING"
  },
  "payment": {
    "id": "clx...",
    "amount": 15000,
    "qrisPayload": "...",
    "qrisExpiry": "2026-04-15T10:30:00Z"
  }
}
```

### Step 5: QRIS Payment

**UI Components:**

- QR code image (generated from `qrisPayload`)
- Amount display
- Countdown timer until QRIS expiry
- "Download QR" button (downloads QR as PNG)
- Help text: "Scan QR ini menggunakan aplikasi e-wallet atau mobile banking Anda"

**Logic:**

1. Generate QR code image from `qrisPayload` string using `qrcode` library
2. Display QR code prominently on screen
3. Start polling `GET /api/payments/[paymentId]/status` every 3 seconds
4. Show countdown timer based on `qrisExpiry`
5. If QRIS expires → show "QR kadaluarsa" with option to regenerate

**QR Download:**

- Generate high-res QR PNG (512x512)
- Include ticket info below QR: plate, amount, location name
- Trigger browser download

### Step 6: Payment Confirmation

When payment succeeds (via polling or webhook redirect):

1. Navigate to `/tiket/[ticketId]`
2. Generate approval code:
   - `approvalCode`: random 4-digit number (e.g., `4827`)
   - `timeoutCode`: 4 digits derived from expiry timestamp (e.g., last 4 digits of `validUntil.getTime()`)
3. Display approval info

### Step 7: Approval Code Display (`/tiket/[ticketId]`)

**UI Components:**

- Large numeric approval code: `4827 - 6301` (approval + timeout)
- QR code containing the same codes
- Ticket details: plate, vehicle type, valid from → valid until
- "Simpan ke galeri" button (screenshot/share)
- Status indicator: valid / expired

**Verification at exit:**

- Attendant/gate scans the QR code or visually checks the numeric code
- QR payload format: `PARKIR:{ticketId}:{approvalCode}:{timeoutCode}`

## Client State Management

Use React state in a client component (multi-step form):

- No global state store needed
- Step navigation: linear forward, can go back to edit
- Form data persisted in state until submission
- After payment, ticket ID stored in URL params

## Error Handling

- Location not found → custom 404 page
- Payment timeout → allow retry with new QRIS
- Network errors → show retry button, don't lose form state
- Invalid plate → show validation message
