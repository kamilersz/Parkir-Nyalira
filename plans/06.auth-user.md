# 06. Auth & User Features

## Overview

Authentication via Better Auth (already set up) with additional parking-specific user features: saved plates, quick selection, and parking history.

## Auth Configuration

Already configured in `src/server/better-auth/config.ts`:

- GitHub OAuth
- Email/password

### Changes Needed

1. Make GitHub OAuth credentials optional in development (use `z.string().optional()` for dev)
2. Add `BETTER_AUTH_URL` env variable for production callback URLs
3. Keep auth pages under `(auth)` route group

### Login (`/login`)

- Email/password form
- "Masuk dengan GitHub" button
- Link to register
- After login: redirect to previous page or home

### Register (`/register`)

- Name, email, password form
- "Daftar dengan GitHub" button
- After register: redirect to home or onboarding

### Auth Callback

Already handled by `/api/auth/[...all]/route.ts`.

## User Features

### Saved License Plates

When a logged-in user creates a ticket, automatically save/update their plate:

1. After ticket creation, upsert `LicensePlateHistory`:
   - If plate exists for user: increment `useCount`, update `lastUsedAt`, update `vehicleType`
   - If new plate: create record

### Quick Plate Selection

On the parking flow Step 2, if user is logged in:

1. Fetch saved plates: `GET /api/user/plates`
2. Show "Plat tersimpan" section above the plate input
3. Each saved plate shows: raw plate, vehicle type badge, label
4. Clicking a plate auto-fills the input and selects the vehicle type

### Plate Management

`GET /api/user/plates` — List user's saved plates
`POST /api/user/plates` — Manually add a plate
`PATCH /api/user/plates/[id]` — Update label
`DELETE /api/user/plates/[id]` — Remove saved plate

### Parking History (`/riwayat`)

Requires auth. Shows user's past tickets:

**Filters:**

- Date range
- Status
- Location

**Table:**

- Location name
- License plate
- Vehicle type
- Duration
- Amount
- Status
- Date
- Link to view ticket

**API:** `GET /api/user/tickets?page=1&limit=10&status=PAID`

## Anonymous vs Authenticated

The parking flow works for both:

| Feature               | Anonymous | Logged In    |
| --------------------- | --------- | ------------ |
| Create ticket         | ✓         | ✓            |
| Pay with QRIS         | ✓         | ✓            |
| View ticket (via URL) | ✓         | ✓            |
| Quick plate selection | ✗         | ✓            |
| Parking history       | ✗         | ✓            |
| Admin access          | ✗         | ✓ (if admin) |

- `ParkingTicket.userId` is nullable — anonymous tickets have `null`
- After login, prompt to claim anonymous tickets? (Future consideration)

## Better Auth Schema

The existing Better Auth models (`User`, `Session`, `Account`, `Verification`) remain unchanged.

### User Model Extensions

The `User` model from Better Auth already has `id`, `name`, `email`, `image`. No additional fields needed — parking-specific data lives in related tables (`LicensePlateHistory`, `ParkingTicket`, `LocationAdmin`).
